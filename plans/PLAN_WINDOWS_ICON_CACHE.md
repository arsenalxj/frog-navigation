# Windows 图标缓存加载修复

状态：已实施，2026-09-15 在 Windows x64 Release 完成隔离验证。

用途：消除网络请求阻塞已有图标缓存的问题，让正常收起后保留的位图在再次展开首帧直接显示。适用于 Windows；功能移除或方案被整体替代时同步清理本文件。

## 已验证的原因

相同安装程序、书签与缓存副本，在联网时“工作”四张图标约 8.8 秒后显示，离线时正常显示。27 张 PNG 缓存均有效。旧模块重放显示，四张图排队约 12.47 秒，而每张读取、解码仅需 0.12～0.31 毫秒。

`Images::run` 原有两个线程同时读取缓存和执行同步网络请求，前面的无缓存条目占满线程，后面的缓存命中任务也必须等待。`Launcher::hide` 原先释放绘图位图，每次重新展开都再次走该加载流程。

本机原始证据位于 `windows/build/verification/icon-delay-20260915/report.md`。诊断目录为忽略的本地验收产物，含真实书签信息，不随交付包发布。

## 最终实现

### 独立读取缓存

`windows/src/platform/Images.h`、`Images.cpp` 使用 1 个专用缓存线程和 2 个慢任务线程，各自的队列与条件变量负责调度。普通请求先读 PNG；命中立即完成，缺失或损坏才转交网络队列。壁纸读取与模糊在慢任务队列合并并优先调度，网站网络并发仍最多为 2。

缓存队列最多排队 128 项；慢任务队列最多排队 128 项普通图标，另允许一个合并的壁纸任务。线程空闲时休眠。读取、解码、联网、磁盘写入及回调均在任务队列锁外执行；PNG 发布与清理由独立锁串行化，避免旧下载覆盖新下载成功写入的缓存。

请求返回唯一标识，0 表示没有接收。相同 URL 的重复请求合并；尺寸升级或显式刷新使旧请求失效。缓存缺失但网络队列已满时返回可重试结果，界面按 100 毫秒补交当前可见的缺失图标。

### 收起时保留有效绘图资源

`windows/src/ui/Launcher.h`、`Launcher.cpp` 在正常收起时保留 Direct2D 绘制表面、图标位图、壁纸及配套资源。重新展开直接绘制尺寸足够的已有位图。退出、设备失效、DPI 变化等需要重建时释放；调整表面尺寸或绘制结束发生资源失效时，也重新加载图标与壁纸。

内存图标最多 128 张，记录最近使用顺序，优先淘汰当前页面不需要且最久未使用的位图。普通图标及文件夹前四张缩略图统一参与可见性判断和使用记录。被淘汰图标从 PNG 异步恢复。

选择完整保留的依据是本机对照实验：收起 30 秒后，释放模式私有内存约 31.25 MiB，完整保留约 31.52 MiB，已提交专用显存均约 18.11 MiB。本机未测出每次收起释放的明显收益，详见诊断目录 `memory-report.md`。整个绘图表面的开销仍随窗口大小和驱动变化；128 张限制只约束图标数量。

### 取消与刷新

收起时暂停图片任务、清空两个队列并递增请求代次，同时停止动画和补交定时器。进行中的同步网络调用依现有超时结束，其等待只占用慢任务线程。任务转交、PNG 发布前和结果处理均检查有效性，UI 同时校验代次与请求标识。

右键刷新成功后替换位图及磁盘缓存，失败保留旧图。离线模式只读缓存。现有缓存目录、URL 哈希文件名与 PNG 格式继续使用，沿用当前源码的网站直连及 SVG 支持。

诊断默认关闭；启用时记录缓存路径、请求来源、排队/处理/总耗时和请求标识。首帧事件在 `EndDraw` 成功后记录绘制图标数、真实位图数、位图总数及绘制表面代次，用来核验首帧是否复用。

## 验收结果

- `image-cache` 使用本机 HTTP 服务的同步信号确认两个请求确实等待响应，再请求预置缓存；旧实现失败，新实现在释放网络响应前完成缓存读取。覆盖快速重开、去重和尺寸升级、旧结果丢弃、损坏缓存恢复、刷新失败保留旧图，以及队列上限和可重试反馈。
- `native-smoke` 用 181 个隔离书签遍历页面，验证首帧复用、128 张淘汰上限及淘汰后的重新读取。通过带合法 RECT 的 `WM_DPICHANGED` 消息验证重建路径和图标恢复；原有表单、拖拽、冲突恢复与退出检查继续通过。
- 实际 38 个书签及 27 张 PNG 的副本：首页命中 25 张，联网全部在 12.86 ms 内返回，离线全部在 12.20 ms 内返回，达到本组缓存请求 ≤100 ms 的验收目标。
- 联网“工作”四张图标的缓存请求耗时为 12.18～12.86 ms；新进程首次可操作绘制已使用首页全部 25 张已有缓存。三次再次展开为 14.92～15.35 ms，首帧均使用四张真实位图，绘制表面代次不变，且没有重复磁盘读取。
- 实际副本联网收起 30 秒：私有提交 33.53 MB（31.97 MiB），工作集 62.54 MB，专用显存提交 18.11 MiB，共享显存提交 2.82 MiB；随后 10 秒单核口径 CPU 采样为 0%。
- 1,000 个隔离书签：进程启动至可操作 176.98 ms，再次展开 20.25～29.19 ms，收起 30 秒私有提交 33.92 MB，10 秒后台 CPU 为 0%，均满足 Windows 主方案已有目标。这组为离线且没有图标缓存，图标保留成本以实际数据副本测量为准。

详细记录见 `windows/VALIDATION.md`、本机诊断目录 `fix-report.md` 和 `windows/build/performance/20260915-175337/report.json`。首次启动或位图已经淘汰时仍异步读盘，本次消除的是网络引起的数秒等待，不承诺所有设备每次冷启动均零占位。

## 交付与适用边界

构建及 CTest 使用隔离数据；交付为 `windows/build/Release/Frog.exe` 和 `windows/dist/Frog-windows-x64.zip`。当前交付尚未安装。

本机为 1920×1080、100% 缩放、AMD Radeon HD 7670。DPI 测试覆盖消息触发的重建代码路径，尚未验证真实跨屏缩放切换、驱动重置或高 DPI 多显示器资源成本。若其他设备测出完整保留的明显成本，可改为有上限的 CPU 像素缓存并在收起时释放绘图资源；代价是重新展开需要重建位图，是否采用以该设备实测收益决定。
